## 明显风险示例

- `Graph Theory/二分图.cpp` 的全局 `color` 默认为 0，却用 `-1` 判断未染色，导致 DFS 不会启动。
- `Graph Theory/强连通分量tarjan.cpp` 只调用 `tarjan(1)`，会漏掉其他连通分量。
- `Data Structure/线段树1.cpp` 存在非法声明 `typedef int long long`，且类型意图混乱。
- `Graph Theory/dijkstra单源最短路径.cpp` 使用 `int` 距离，路径和可能溢出，也没有多测初始化接口。
- `String/Trie.cpp` 清空字符转移时只循环到 62，遗漏 63 号列；字符映射与数组大小也需要重新核对。
- `Trees/虚树.cpp` 把虚树构造与一道特定题目的 DP 混在一起，不能直接视为通用模板。
- `Graph Theory/费用流.cpp` 的 `work` 先执行一次增广后又把答案清零，逻辑明显需要重新验证。
- 多份代码固定只从 1 号点遍历、使用递归处理大图、依赖全局零初始化，且没有明确多测清空规则。
- `generate_pdf.py` 写死了旧路径 `D:\\CF\\templates`，当前目录下不能直接作为正式生成流程使用。

本次只迁移 DSU、Fenwick、Dijkstra、KMP 和快速幂。它们已与题目输入输出解耦，并补充本地测试；在获得明确在线评测验证题和队友复核前，状态保持 `Unverified`。
